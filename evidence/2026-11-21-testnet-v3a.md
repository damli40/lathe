# Lathe V3a on X Layer testnet: deploy, smoke run and the crank on a public chain

Date: 2026-11-21. Chain: X Layer testnet, chainId 1952, RPC `https://testrpc.xlayer.tech/terigon`. Code: commit `f813ebe`.

## What this proves, and what it does not

- **Proves:** on a real public network, an order made of two pieces is paid only after both pieces pass; a wrong piece is refused while the other piece stays passed; a paid two-piece rule answers free `run` calls; and the crank script (`scripts/crank.mjs`) checks a 4,096-case piece to Paid in 5 transactions, each sent with a gas limit of about 200M. That last point was untested before: a public X Layer chain accepts transactions that reserve nearly a whole 210M block. All V0, V1 and V2 flows were rerun on the new contract and still work. The contract is now three deployed pieces: `LatheOrders` plus two linked libraries.
- **Does not prove:** anything about real TapeOut circuits. TapeOut is not on testnet (`2026-11-20-preflight.md`), so every circuit here is a stand-in. The stand-in formula circuits report 4 gates, so each case reserves 160,000 gas; a real circuit with more gates fits fewer cases per transaction (`2026-11-21-gas-16-input-piece.md` has the measured numbers for a real 652-gate circuit). Mainnet behaviour of 200M-limit transactions is not shown by this run.

This contract replaces the V2 testnet contract `0x8EC54D31af81b0de2Eda8133fAa7fb86bbD8EC0a` (`2026-11-21-testnet-v2.md`), which stays on chain. The page (`web/config.js`) now points at the new address.

Deployer, buyer and builder in every order: the throwaway testnet wallet `0x5a15Dca0F83Ae5878fD20eF0f9444b59Dbef03a0`. Fee: 1%.

## The crank on a public chain

Command (keystore file and password file, no raw key on the command line):

```sh
node scripts/crank.mjs --lathe 0x1E96e90E25E25b6fcb8cc28aa883d5a5df2715f4 --order 8 --piece 0 --batch 1000 \
  --rpc https://testrpc.xlayer.tech/terigon --chain-id 1952 --keystore <file> --password-file <file>
```

It read chain id 1952 and block gas limit 210,000,000, lowered the batch from 1,000 to 940 cases so the gas limit stayed under its 200M default, and sent 5 transactions in 55.6 seconds:

**Order 8 = 2 (Paid)** afterwards. What the gap between used and limit means: each case must be handed its whole safety budget (160,000 gas here) before the circuit runs, so a transaction reserves about 30 times what it ends up using. The fee is charged on gas used, so the cost stays low; the reservation only limits how many cases fit in one transaction.

## Limits

- Stand-in circuits only, with 4 gates each (see above).
- Source not verified on OKLink (no API key yet); verifying a contract with linked libraries there is untested.
- The page's no-wallet read test passed against this contract for orders 1 to 3. The page's pieced-order views were tested on a local chain only, not against these live orders.
- No order was created through the page on testnet with a real wallet.
